## 全项目业务分析（Interview Agent）

对 `D:\workplace\trae` 做了完整的业务层面分析（非代码审查），产出分层架构图 + 双路召回断点图。

### 项目定性
面向求职者的**本地私有知识库 + 面试题库 RAG 助手**。前端 React18+Vite+Tailwind+shadcn/ui+AI SDK，后端 Node+Express，全链路本地化（Ollama + SQLite + vectra 落盘），单用户无登录。

### 关键业务结论（已核实，非推测）
1. **题库引擎是死链路（最严重断点）**
   - `server/data/interview/questions.json` = `{"seq":0,"questions":[]}`
   - `questionBank.js:59` 定义了 `SEED_QUESTIONS`（约 20 题），但全仓库无任何引用点
   - `questionBank.js` 导出了 `addQuestion()` / `deleteQuestion()`，但**没有任何 HTTP 路由调用**，即无录入入口
   - 结果：interview-retrieval 的双路召回中，结构化题库一路恒返回 0 条，实际只有知识库向量一路在供料
2. **PDF / DOCX / XLSX / PPTX 明确拒绝**（index.js:266，列为 BINARY_TEXT_EXT 直接 400），仅支持 md/txt/html/csv/tsv/log/json/yaml —— 面试场景最大的产品化缺口
3. **vite.config.js:22** proxy target 写 `3001`，注释与后端默认端口均为 `3000`，联调易踩坑
4. 实盘数据：26 篇文档 / 67 切片 / vectra 索引 67 条（一致）；会话 19 个、消息 65 条、annotations 18 条
5. 已完成度约 70%。docs/代码问题清单.md 中 H1~H4、M1~M7、L1~L7、S1 全部标记已修复，仅剩 N1（knowledgeApi/sessionApi 未接入统一 api.js，导致 src/lib/api.js 成死代码）、N2（debug 日志未提前短路）

### 架构要点（备查）
- 无 react-router，`AppShell.jsx` 用 `view` state 三态切换：chat / dashboard / knowledge
- 智能体 4 个：interview-retrieval、doc-processor 可用；resume-analysis、mock-interview 占位。knowledge-base 已降级为全局基础设施，不再是聊天智能体
- 引用溯源不走 HTTP，经 SSE 的 `2:` annotation 行下发；前端 `useChatWithAnnotations` 拦截 fetch 剥离首行
- 检索：query 改写 → 3 条变体 → 每条过采样 `max(topK*10,50)` → 按 chunk.id 累加 `score×weight`（权重 1/0.8/0.6）→ category/tag 过滤在合并后统一做 → clamp [0,1]
- 切片：三层递归（标题→段落→Intl.Segmenter 句子）+ 语义细切（相邻句余弦，阈值 mean-1×std，下限 0.5）+ 短块合并 + hardMax 2000 + 上下文扩展（前后各 2 句 ≤120 字）
- chunk 向量 = 句向量算术平均，零额外 embedding 开销
- 降级：无 Key → hash embedding（256 维 FNV-1a）+ stub LLM 摘录式输出
