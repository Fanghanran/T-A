# 上传切片策略设计文档

> 日期：2026-08-25
> 状态：已实现

---

## 背景

当前上传文档时，切片策略是硬编码走**语义感知切片**（三层递归：标题→段落→句子，超限则语义细切）。用户没有选择权，无法针对非 Markdown 文档（如 Q&A 格式、列表格式、代码文件）做出合适的切片。

需求：上传时支持两种切片策略，用户可选：
1. **默认方案**：现有的语义感知切片（保持兼容）
2. **自定义标识符切片**：用户手动输入分隔符字符串，按该字符串切分

同时支持自定义 `maxChars`，并在上传前提供切片预览。

---

## 用户流程

```
1. 用户选择文件
2. 填写分类、标签
3. 选择切片策略：
   ├─ 默认方案（语义感知切片）→ 显示默认参数（只读，来自 chunkerConfig）
   └─ 自定义标识符 → 显示输入框：
       ├─ 分隔符（必填，如 "---"、"##"、"\n---\n"）
       ├─ 目标字数 maxChars（默认 1000，可改）
4. 点击「预览切片」按钮
   → 后端实时切片，返回 chunk 列表（含 heading、text、字符数）
   → 前端弹窗展示预览
5. 确认无误后点击「上传」
   → 后端走完整链路：切片 → embedding → topic/questions 标注 → 入库
   → 返回新建文档对象
```

---

## 接口设计

### 新端点：预览切片

```
POST /api/knowledge/preview-chunks
Content-Type: application/json

请求体：
{
  "text": "文档纯文本内容（前端读取文件后传给后端，不上传到存储）",
  "strategy": "semantic" | "delimiter",
  "delimiter": "用户输入的分隔符（strategy=delimiter 时必填）",
  "maxChars": 1000  // 仅 strategy=delimiter 时使用；semantic 时走 chunkerConfig
}

响应：
{
  "chunks": [
    {
      "idx": 0,
      "heading": "第 1 部分",
      "text": "切片内容...",
      "chars": 320,
      "preContext": "",
      "postContext": ""
    },
    ...
  ],
  "total": 5
}
```

**说明**：
- 前端用 `FileReader` 读取文件为文本，传给这个接口
- 只返回切片结构，**不写入任何存储**（零副作用）
- `maxChars` 超过 5000 或低于 50 时返回 400 错误

---

### 修改端点：上传文档

```
POST /api/knowledge/documents
Content-Type: multipart/form-data

字段：
  file            文件（必填）
  category        分类（可选）
  tags            标签 JSON 字符串（可选）
  chunkStrategy   "semantic" | "delimiter"（可选，默认 "semantic"）
  delimiter       分隔符字符串（chunkStrategy=delimiter 时必填）
  maxChars        目标字数（可选，默认 1000）

响应：与原接口一致，返回新建的文档对象
```

## 后端改动

### 1. `server/lib/chunker.js` — 新增 `splitByDelimiter` 函数

```
新增导出函数：
  splitByDelimiter(text: string, delimiter: string, opts?: { maxChars?: number })
    → { heading: string, text: string }[]

行为：
  - 按 delimiter 字符串切分文本
  - 每个 chunk 的 heading：取该段第一行（trim 后），若无则用 "第 N 部分"
  - 如果 opts.maxChars 有值且某段超长，按段落（\n\n）再切一刀
  - 返回的 chunk 不带 semantic 细切（自定义模式下不做语义分析）
```

### 2. `server/lib/chunker.js` — `splitDocumentIntoChunks` 接受新参数

```
opts 扩展：
  strategy: 'semantic' | 'delimiter'   // 默认 'semantic'
  delimiter: string                     // strategy=delimiter 时使用
  config.maxChars: number               // 可覆盖 chunkerConfig.maxChars

逻辑分支：
  if strategy === 'delimiter':
    ruleBlocks = splitByDelimiter(text, delimiter, { maxChars: config.maxChars })
    // 自定义模式下跳过语义细切（不做 embedding），直接进上下文扩展
    // sentenceVectors 留空，后续用 embedTexts 整体 embed
  else:
    ruleBlocks = recursiveSplit(text, config)  // 原有逻辑
```

### 4. `server/index.js` — 新增 `previewChunks` 端点

```js
app.post('/api/knowledge/preview-chunks', express.json({ limit: '4mb' }), async (req, res, next) => {
  const { text, strategy = 'semantic', delimiter, maxChars } = req.body ?? {}
  if (!text || typeof text !== 'string') return res.status(400).json({ message: 'text 必填' })
  if (strategy === 'delimiter' && (!delimiter || !delimiter.trim())) {
    return res.status(400).json({ message: 'strategy=delimiter 时 delimiter 必填' })
  }

  const cfg = { ...chunkerConfig }
  if (strategy === 'delimiter' && maxChars) {
    const n = Number(maxChars)
    if (n < 50 || n > 5000) return res.status(400).json({ message: 'maxChars 范围 50~5000' })
    cfg.maxChars = n
  }

  // 只切片，不 embed 不入库
  const splitRes = await splitDocumentIntoChunks(text, {
    strategy,
    delimiter: strategy === 'delimiter' ? delimiter.trim() : undefined,
    config: cfg,
  })

  const { chunks } = splitRes
  res.json({
    chunks: chunks.map(c => ({
      idx: c.idx,
      heading: c.heading,
      text: c.text,
      chars: c.text.length,
      preContext: c.preContext || '',
      postContext: c.postContext || '',
    })),
    total: chunks.length,
  })
})
```

## 前端改动

### 1. `src/lib/knowledgeApi.js` — 新增 previewChunks 方法

```js
/**
 * 预览切片（不入库）
 * POST /knowledge/preview-chunks
 * @param {string} text 文档纯文本
 * @param {{strategy:'semantic'|'delimiter', delimiter?:string, maxChars?:number}} opts
 */
export function previewChunks(text, opts = {}) {
  return postJson('/knowledge/preview-chunks', {
    text,
    strategy: opts.strategy || 'semantic',
    ...(opts.strategy === 'delimiter' && { delimiter: opts.delimiter }),
    ...(opts.maxChars && { maxChars: opts.maxChars }),
  })
}
```

### 2. `src/lib/knowledgeApi.js` — `uploadDocument` 透传新字段

```js
export function uploadDocument(file, meta = {}) {
  const form = new FormData()
  form.append('file', file)
  if (meta.category) form.append('category', meta.category)
  if (meta.tags?.length) form.append('tags', JSON.stringify(meta.tags))
  if (meta.chunkStrategy) form.append('chunkStrategy', meta.chunkStrategy)
  if (meta.delimiter) form.append('delimiter', meta.delimiter)
  if (meta.maxChars) form.append('maxChars', String(meta.maxChars))
  return postForm('/documents', form)
}
```

## 兼容性说明

- 上传接口新增字段全部可选，不传时走原有默认语义切片逻辑，**零破坏性变更**
- 预览接口是新增的，不影响任何现有功能
- `chunker.js` 的 `splitIntoChunks`（旧兼容接口）签名不变，内部已支持新参数但不使用（由 `prepareDocChunksAndVectors` 统一走新接口）
