# 用户模块设计（v1）

> 目标：把已有的用户基础设施（M5a 令牌 / owner 隔离 / 配额 / 审计归属）补成完整可感的用户模块。
> 原则：维持 ADR-008（不做密码 / OAuth / JWT）、AUTH_MODE 三档递进不变、disabled 模式零回归。

## 1. 现状盘点

### 已有（不重做）

| 资产 | 位置 | 状态 |
|---|---|---|
| 用户令牌签发/吊销（sha256 落库，明文仅显一次） | `lib/principal.js` | 可用 |
| 认证三档：disabled / user-token / jwt（预留） | `AUTH_MODE` env | 可用 |
| owner_id 数据隔离（SQLite + Milvus 过滤） | ADR-008，全存储层 | 可用 |
| 全局配额（文档数 / 切片数，env 配置） | `lib/quota.js` | 可用，**非 per-user** |
| 审计带 ownerId（AsyncLocalStorage 透传） | `lib/management/audit.js` | 可用 |
| 管理端用户端点（列表 / 签发 / 吊销，adminAuth 保护） | `manager.js /users*` | 可用 |
| 前端令牌输入弹窗（401 触发） | `AuthTokenDialog.jsx` | 可用 |
| 前端用户区块（塞在参数管理页内） | `UsersSection.jsx` | 可用但不成体系 |

### 缺口

1. **前端无「当前身份」概念** —— user-token 模式下看不到自己是谁、用量多少、当前浏览的是谁的数据；只有 401 被动弹窗
2. **用户管理不是一级菜单** —— 混在参数管理页里，无每用户用量展示，无配额视图
3. **配额全局一刀切** —— env 配置对所有用户相同，无法按用户收紧/放宽
4. **后端无 /me** —— 前端无法主动查询当前身份与用量
5. **无角色字段** —— admin（ADMIN_TOKEN）与普通用户（令牌）的区分只存在于机制里，无数据表达

## 2. 分期总览

| 期 | 内容 | 新增/改动 | 量级 |
|---|---|---|---|
| U1 | 当前身份 + 用户中心（前端可感层） | `GET /api/me` + Header 用户菜单 | 小 |
| U2 | 用户管理一级页（管理员视角） | `/management/users` 路由 + 用户列表升级 | 中 |
| U3 | per-user 配额覆盖 | users.json 扩展 + quota.js 读取 + 管理端编辑 | 中 |
| U4 | 角色字段预留 | users.json 加 role（仅存储，不做鉴权分支） | 极小 |

## 3. U1 —— 当前身份 + 用户中心

### 数据流

```
前端启动 → GET /api/me（携带令牌，若有）
  → disabled 模式：{ mode:'disabled', userId:'local', usage, limits }
  → user-token 模式：令牌解析 → { mode, userId, label, usage, limits }
    （令牌无效 → 401 → 现有 auth:required 弹窗，行为不变）
→ Header 右侧用户徽标渲染
```

### 落位

- 后端：`GET /api/me` 挂在数据路由层（**不挂 adminAuth** —— 普通用户可访问）；复用 `principalOf` + `usageOf`
- 前端：
  - Header 右侧用户徽标（图标 + userId），点击下拉：当前身份卡片（userId / 模式 / 用量进度条 / 令牌状态）、「切换令牌」（复用 AuthTokenDialog，增加手动入口）、「清除令牌」（回 local / 触发 401）
  - 新 hook `useCurrentUser()`：拉 /api/me，401 时静默（交给弹窗）
- disabled 模式：徽标显示 `local`，菜单显示「单用户模式」说明 —— 不留死角

## 4. U2 —— 用户管理一级页

- 路由 `/management/users`；侧边栏「系统管理」目录第 6 项（图标 Users）
- 页面内容（管理员视角，adminAuth 保护不变）：
  - 模式横幅：disabled 模式给开启指引（现 UsersSection 文案迁移）
  - 用户表：userId / 备注 / 状态（active·已吊销）/ 创建时间 / **用量列**（documents/chunks + 配额进度条，数据来自 usageOf）
  - 操作：签发（明文 token 仅显一次，现有交互保留）、重签（吊销后同 userId 可再签）、吊销（两步确认，复用页内两步式交互模式）
  - 审计联动：本页操作走现有 appendAudit（user.issue / user.revoke）
- `UsersSection.jsx` 从参数管理页移除（职责整体迁出）

## 5. U3 —— per-user 配额覆盖

- users.json 条目扩展：`quota: { maxDocuments?: number, maxChunks?: number }`（缺省 = 用 env 全局值）
- `quota.usageOf(ownerId)`：优先读该用户的覆盖值（principal.js 新增 `quotaOverridesOf(userId)`），回退 env
- 管理端：`PATCH /api/management/users/:userId/quota`（adminAuth），用户管理页内联编辑
- 失败语义：覆盖值非法（0/负/非数字）→ 400 显式报错，不静默回退；写审计 `user.quota.set`

## 6. U4 —— 角色字段预留

- users.json 条目加 `role: 'member'`（默认）；local 视为系统用户
- 本期**不**做任何 role 鉴权分支（管理权仍由 ADMIN_TOKEN 判定）；仅为未来「多管理员 / 只读访客」留数据结构位

## 7. 明确不做

- 密码、注册、OAuth、JWT（ADR-008 决策维持；令牌即身份，明文只在签发时出现一次）
- 用户间数据共享 / 转移（owner 隔离是硬边界）
- 自助改资料（label 只能管理员改）

## 8. 实施顺序与验收

| 顺序 | 内容 | 验收标准 |
|---|---|---|
| U1 | /api/me + Header 用户菜单 | disabled 模式显示 local；user-token 模式显示正确身份与实时用量；清除令牌后行为与现在 401 流一致 |
| U2 | 用户管理页 | 系统管理菜单出现入口；列表含用量进度条；签发/吊销/重签全可用且审计有痕 |
| U3 | per-user 配额 | 为某用户设低配额后上传触顶返回 429 QUOTA_EXCEEDED；清除覆盖回退全局值 |
| U4 | role 字段 | 新签发用户带 role=member；旧 users.json 兼容读取 |

每期独立交付、独立可回退；U1 是可感层优先落地，U3 依赖 U2 的编辑入口。
