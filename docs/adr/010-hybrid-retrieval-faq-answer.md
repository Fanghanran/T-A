# ADR-010：混合检索与 FAQ 直接应答（「答非所问」修复）

## 状态

**已接受 · 已实施**（2026-09-04）

## 背景

用户在「面试题检索」智能体提问「还招外卖员吗」，知识库（faq.md）里有精确的问答对（「问: 还招外卖员吗 / 答: 在哪个区域呢，发我看下啊」），但系统给出的回答是官僚开场（「未在结构化题库中匹配到题目，已从知识库召回 5 条相关材料…」）+ 空话搪塞（「会因区域而有所差异，请提供详细信息」），答非所问。

排查确认两个独立根因：

1. **Prompt 层**（`llm.js` `streamInterviewAnswer` 的「题库未命中、仅 KB 命中」分支）：
   - 强制官僚开场（「开头第一句必须说明：未在结构化题库中匹配到题目…」）；
   - 挂了 `NO_REF_RULE`——明令禁止复述"Recall 片段原文"，而 FAQ 场景里**片段的"答"就是答案本体**，模型被禁止引用只能润色成空话；
   - "若片段不足以回答要如实说明"进一步诱导对冲式回答。
2. **检索层**（`unifiedSearch.js`）：纯向量对口语短查询不稳定——讲义/PPT 导出的大文档近重复同质块（相似度虚高 44%）霸占 topK，把字面精确命中的短 FAQ 块挤出候选；且关键词匹配若基于 `snippet`（仅截前 240 字）会漏掉块内更深处的目标问答。

## 决策

1. **FAQ 直接应答 prompt**（`streamInterviewAnswer` 题库未命中分支重写，其余分支不动）：
   - 直接回答用户问题本身；禁止出现「根据片段N」「知识库召回/检索到」「未在结构化题库中匹配到题目」等检索过程表述；
   - 片段常为「问:…／答:…」式 FAQ：问句与用户问题相同/高度相似时，**直接以该片段的"答"为答案主体**（可按对话口吻轻微润色），并融合其他片段相关信息补充；
   - 禁止空泛套话（片段已有答案就给出，不用"会因…而异"搪塞）；确实不足才如实说明；
   - 该分支**刻意不挂 `NO_REF_RULE`**（代码注释记录本案例作为依据）。
2. **混合检索**（`unifiedSearch.js` 合并排序后、topK 截断前，两步顺序敏感）：
   - **4.5 CJK 2-gram 覆盖率加权（先做）**：原始 q 的 2-gram 被**片段全文**覆盖的比例 ×0.2 加分（封顶 +0.2）；只用原始 q（不含改写 query）；全文来自 `vectorStore.search` 新增的 `text` 字段（原 `snippet` 只截 240 字，不足）；
   - **4.6 近重复折叠 + 单文档配额（后做）**：snippet 归一化前 64 字作近似键同键留最高分；单 `docId` 最多 3 条，给其他文档让位。
3. **配额/加权顺序敏感**：加权必须在去重/配额**之前**——字面精确命中但语义分低的块才有机会存活进 topK（2026-09-04 实测：先去重时精确块仍缺席）。

## 后果

- 正面：实测同一问题 top1 [100%] 精确命中 faq 问答块（含 2-gram 加分），回答「还在招外卖员哦，请问您所在的区域是哪里呢？发我看一下。」完全对题；近重复同质块不再霸榜；对口语短查询整体更稳健。
- 权衡：2-gram 加分封顶 +0.2，可能轻微改变长尾排序（可接受）；单文档配额 3 在"答案集中在单文档"场景会挤出部分同文档块（候选池 overK=50 已扩大缓解）。
- 检索管道新增 `text` 全文字段透传，内存/传输开销可接受（overK 候选 × 块文本）。

## 重要教训：测试脚手架污染（必须遵守）

排查期间从 Git Bash 用 `curl -d '中文'` 内联发请求，部分调用把中文编码成 GBK 乱码发给后端（响应 `queries:["����…"]` 实锤），导致检索与回答全崩的**假象**——一度据此误判"向量错位/全库坏向量"，后经带 `.env` 的正确测量推翻。**规则**：凡含中文的请求体测试，一律先写 UTF-8 文件再 `curl --data-binary @file`（已录入 `AGENTS.md` / `.trae/rules/code.md` 项目事实）。

## 明确不做（本设计）
完整 BM25 索引、MMR 多样性重排、去重键配置化、跨 query dedup 键外置。
