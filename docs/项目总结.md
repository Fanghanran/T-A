# Interview Agent 项目总结

> 生成日期：2026-09-06
> 项目定位：面试知识库 RAG 系统 —— 文档上传、智能切片、双向量索引、混合检索、流式问答的完整闭环，含多智能体协作与运维可观测能力。

---

## 一、项目概述

本项目是一个面向面试备考场景的知识库问答系统（Retrieval-Augmented Generation），核心能力：

| 能力 | 说明 |
|------|------|
| 文档管理 | 支持 md / txt / pdf / docx 上传，两段式上传（预览确认后入库）、手动录入、批量操作、元数据与正文编辑 |
| 智能切片 | 结构化递归切片（标题→段落→句子）+ 语义细切 + 分隔符切片（支持滑动窗口重叠）+ 零成本上下文扩展 |
| 双向量索引 | 每个切片同时存储 `text_vector`（正文向量）与 `question_vector`（问题锚点向量），支撑混合召回 |
| 混合检索 | 语义召回 + 问题锚点召回 + 2-gram 关键词加权三路融合；低分查询级联触发 HyDE（假设答案检索） |
| 流式问答 | AI SDK data-stream 协议，前端 useChat 直接消费；检索命中以注解卡片形式随流推送 |
| 多智能体 | 默认对话 / 知识库问答 / 面试题检索 / 简历分析 / 模拟面试 5 个内置智能体；文档处理走 ReAct 与 Plan-and-Execute 双工作流 |
| 管理运维 | 工具/工作流启停、19+ 调优参数在线热生效、操作审计、模型管理、向量数据可视化、/metrics 运行指标 |

### 3.3 核心数据流

**上传入库链路（两段式）**：

```
文件 → prepare（抽文本[pdfjs/mammoth/iconv] → 内容哈希查重409 → 切片 → 启发式评分
        → 预览缓存 TTL 30min/上限 50 份，返回 previewId）
     → commit（一次性 previewId → 异步 job：chunking → embedding → indexing → done
        → Q&A解析/LLM生成问题锚点 → 批内去重0.96 → 跨文档去重0.985 → Milvus 双向量写入）
     → 前端轮询 jobs/:id，连续 3 次失败调 cancel API 回滚入库
```

**检索问答链路**：

```
query → queryRewriter（多轮改写，LLM 生成互补 query）
      → 每 query 双路召回（text_vector + question_vector，过采样）
      → 融合（qt=q×0.9；双路 max(t, qt, avg×1.15)）
      → 2-gram 关键词覆盖率加权（+0.2）
      → 多 query 分数累加合并 + category/tag 统一过滤
      → top1 < 0.45 时级联 HyDE（假设答案×0.8 权重融合，TTL 缓存 + 超时熔断）
      → 同文档配额（≤3 条）+ 近重复折叠
      → streamRagAnswer（context 拼装 → streamText → toDataStream
        → prependAnnotation 检索命中卡片）→ pipeStream 落库回调
```

### 3.4 智能体与工作流编排

- **内置智能体**（registerAgent 注册，分发零改动）：defaultChat、knowledgeBase、interviewRetrieval、resumeAnalysis、mockInterview。
- **文档处理双工作流**：单任务走 doc-react（ReAct 循环），复合任务（≥2 意图，extractTaskIntents 判定）走 doc-plan（Plan-and-Execute）；共享设施（LLM provider / 注解构造 / 历史块 / 上下文）抽到 docWorkflowShared；两者均禁用时降级关键词路由，互不影响。
- **运行统计**：registry.resolveRunner 返回包装 run，自动记录 calls / failures / totalMs / lastError，供管理页展示。

### 3.5 管理与可观测性

## 四、关键算法

### 4.1 文档切片体系

**① 结构化递归切片**（semantic 默认策略）：标题 → 段落 → 句子逐级降级，按 maxChars 装箱。核心参数（chunkerConfig，全部在线可调）：

```
maxChars=1000  hardMax=2000  absoluteMax=2500  minChars=100
semanticStdK=1  semanticMinSimilarity=0.5  contextSentences=2  questionsPerChunk=3
```

**② 语义细切**：超长块 embedSentences 逐句嵌入 + 余弦相似度，在「相邻相似度骤降处」（mean − K·std，兜底 0.5）切分，避免机械腰斩。

**③ 零成本上下文扩展**：每块附带前后各 2 句上下文（preContext / postContext），检索命中后可展示更完整语境，不增加向量存储。

**④ 分隔符切片**（delimiter 策略）：
- 字面转义还原（`\n` 两个字符 → 真实换行）+ CRLF 双口径归一；
- overlapChars 滑动窗口重叠（0~500）：后块以前块末尾 N 字符开头；取「前块原始文本」避免链式膨胀，上限压到前块一半防小块整块重复；
- delimiter 全链路禁止 trim（类纯空白分隔符按 length>0 原样传递）。

**⑤ 切片策略持久化**：delimiter/maxChars/overlapChars 写入 doc-strategies.json；4 个入库点写入、3 个重切点（编辑正文 / reindex / 孤儿对账）读取，未记录的旧文档走默认语义策略，杜绝重切漂移。

### 4.2 Q&A 问题解析与双向量索引

- **parseQaQuestion**：多行正则匹配行首「问 / Q / q + 中英冒号」提取问题（≥4 字有效，容忍行首空白，只取第一个问行）。三级策略：
  1. Q&A 格式命中 → `questions=[问题]`，**零 LLM 成本**；
  2. 未命中且开关开 → generateChunkAnnotations（LLM 生成，withQuestions 只控制 LLM 路径）；
  3. topic 兜底用 heading。
- **双向量**：每块 `text_vector`（正文嵌入）+ `question_vector`（问题锚点嵌入）双字段入库，检索时双路召回。
- **实测效果**：题库文档 reindex 后 185/185 块 question_vector ≠ text_vector；口语化提问（问法与正文语体差异大）top1 相似度达 **0.9782**。

### 4.3 混合检索融合（unifiedSearch）

单 query 双路召回后融合（qt = q × QUESTION_WEIGHT）：

```
仅正文命中   → t
仅锚点命中   → qt × 0.9
双路命中     → max(t, qt, ((t + qt) / 2) × (1 + 0.15))    // 平均后小幅加成，防饱和
```

- **2-gram 关键词加权**：查询与切片的字符级 2-gram 覆盖率 1 → +0.2，补语义模型对专有名词/编号的不敏感。
- **多 query 合并**：改写产出的多个 query 命中同 chunk 分数累加。
- **过滤口径**：category/tag 在合并后统一过滤（不是每路过滤），避免漏分。
- **折叠与配额**：同 docId 最多 3 条（单文档霸屏防护）；同 snippet 前缀近重复折叠留最高分。
- **饱和教训**：BOTH_HIT_BONUS 早期取 0.5 导致双路命中直接顶到 1.0、三条结果同分排序失效，收敛为 0.15。

### 4.4 HyDE 级联检索（查询侧增强）

针对「问法与正文语体差异」且不动数据侧的补充方案：

- **级联触发**：首轮（含 2-gram 加权后）top1 分数 < hyde.minScore（默认 0.45）才启动 —— 高分查询零额外开销（实测验证）；
- **生成**：LLM 对用户问题生成 300 字内陈述句假设答案（chat.rewrite 模型角色）；
- **检索**：假设答案向量查 text 路，命中分 × HYDE_WEIGHT(0.8)，同 id 取 max，过滤口径与首轮一致，再走统一折叠配额；
- **防护**：TTL LRU 缓存 64 条 / 10 分钟；超时熔断（默认 12000ms）绝不抛错，失败保留首轮结果；
- **实测**：本地 14b 生成需 8s+（5000ms 必熔断，故调至 12000）；缓存命中 166ms；低分查询检索质量显著提升。

### 4.5 Query 改写（queryRewriter）

- 多轮对话场景结合 history 把「它 / 这个概念」等指代改写为完整独立查询；
- LLM 生成 1~2 个互补 query 并行检索；
- 总开关 / LLM 不可用时降级单 query（显式降级路径，非静默）。

### 4.6 三层去重体系

| 层 | 机制 | 阈值 |
|----|------|------|
| 文档级 | sha256 内容哈希秒断（prepare / commit / 旧上传三处拦截） | 完全一致 → 409 {duplicate, existingId} |
| 批内 | 余弦相似度去重（dedupWithinBatch） | ≥ 0.96 |
| 跨文档 | Milvus 检索比对（dedupPreparedChunks），REST 与聊天侧 CommitToStore 同口径 | ≥ 0.985 |

另提供存量治理：/duplicates/scan 两两余弦扫描 + /duplicates/delete 保留一条清重复。

### 4.7 切片质量评分

启发式可解释评分（0~100，附 level 与 issues）：**字数适配 50 分 + 结构信息 30 分（标题/列表/代码块）+ 文本完整性 20 分（截断/腰斩检测）**。评分结果两级缓存（内容签名 TTL/LRU，10 分钟），外部 embedding 可用时叠加语义信号升级为混合评分（scoreMode: heuristic | hybrid）。

### 4.8 增量向量复用

编辑正文（PATCH content）时先取旧向量建 Map(text→vector)；重切后文本未变的块跳过 embedding 直接复用旧向量，只嵌入变化的块（改错别字不再全篇重嵌）；存储层仍执行全删全写，保证库里只有一套新向量。

### 4.9 两段式上传与任务状态机

- **prepare**：抽文本 + 切片 + 评分，零向量开销，PDF/DOCX 也可先预览；正文缓存模块级 Map（TTL 30 分钟 / 上限 50 份）。
- **commit**：previewId 一次性使用防重复提交；async=true 返回 202 + jobId。
- **job 状态机**：`chunking → embedding → indexing → done | error`，完成任务保留 10 分钟；job 按 owner 隔离。
- **取消回滚**：`POST jobs/:id/cancel` —— 进行中标记取消（入库前拦截 / 入库后回滚删除）、已完成直接删除已入库文档、已失败幂等返回。
- **前端容错**：轮询失败不立即报错，连续 3 次（间隔 2s）才判定失败并调 cancel 回滚，保证「前端显示失败 ⇒ 库里一定没有数据」的前后端一致性。
- **job 恢复与兜底核对**：commit 拿到 jobId 即登记 sessionStorage（`upload:pending-jobs`），done/error/最终判定后移除；页面刷新/轮询中断后挂载时自动恢复轮询（后端 job 保留 10 分钟）；轮询断线或 job 过期（404）时按「标题全等 + uploadedAt ≥ startedAt−5s」核对文档列表——实际已入库则判成功并刷新列表，杜绝「数据在库里、前端却报失败」的误报。
- **轮询禁缓存**：`getUploadJob` 请求带 `cache: 'no-store'`——后端响应默认带 ETag，浏览器会对轮询发起 304 协商并透明返回缓存的旧状态。

### 5.2 存储与基础设施

| # | 问题 | 根因 | 解决 |

### 5.3 Windows 中文与编码

| # | 问题 | 根因 | 解决 |

## 八、优化方向

### 8.1 检索质量

1. **重排序（Rerank）**：召回后引入 cross-encoder（如 bge-reranker）精排，当前纯向量融合对「语义近但答非所问」的区分有限；
2. **稀疏检索混合**：补 BM25 / Milvus 稀疏向量路，强化专有名词与编号类精确匹配（2-gram 加权是其轻量替代）；
3. **检索评测框架**：建立标准问题集，量化 recall@k / MRR / 端到端答案质量（RAGAS 式），让参数调优从「实测个案」走向「回归可比」；
4. **HyDE 策略演进**：假设答案生成与缓存命中率纳入 /metrics 长期观察，评估按 query 语义聚类的缓存键优化。

### 8.2 切片与索引

5. **切片策略自动推荐**：上传时按文档结构特征（问答密度/标题层级/段落长度）自动建议策略预设，替代人工试错；
6. **问题锚点增强**：Q&A 解析目前单问行，可扩展多问题块与问题改写变体入库；
7. **父子切片（small-to-big）**：小块检索、大块喂给 LLM，兼顾召回精度与上下文完整性。

### 8.3 工程与运维

8. **指标外接**：/metrics 目前为 JSON 快照，可加 Prometheus exposition 格式对接 Grafana 看板与告警；
9. **审计与操作的时序对比**：调优参数变更前后检索质量对比报表（依赖评测框架落地）；
10. **多用户增强**：user-token 模式已具备数据隔离，可补用户级配额、文档级 ACL 与共享空间；
11. **CI/CD**：check:all 已具备门禁形态，可接 GitHub Actions 全量流水线 + 镜像发布；
12. **LLM 并发与预算**：本地 14b 串行推理是低分查询 8s 延迟的主因，可评估小模型专职改写/HyDE（质量足够、速度数倍提升）。

### 8.4 前端体验

13. **引用溯源 UI 强化**：注解卡片已有折叠面板，可加原文定位跳转与命中高亮；
14. **流式中断恢复**：长回答会话级断点续传（会话已持久化 SQLite，具备基础）。
