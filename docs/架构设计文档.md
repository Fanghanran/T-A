> 版本：1.0（2026-09-06）

> 强制性编码约束、分层规则细则与门禁命令以项目根 `ARCHITECTURE.md` 为准；重大技术决策背景见 `docs/adr/`；实施排期见 `docs/ROADMAP.md`。

## 一、系统概述

Interview Agent 是一个基于 RAG（检索增强生成）的面试助手平台，核心能力：

1. **知识库管理**——文档上传（两段式：预览确认 → 异步入库）、语义/分隔符切片、双向量索引、编辑重切、批量治理。
2. **智能问答**——统一混合检索（语义 + 关键词 + FAQ 直接应答）+ 本地 LLM 流式生成，答题时引用知识库切片。
3. **多智能体**——插件化注册表（前端 Sidebar / 后端 chat 路由双端注册），支持简历分析、模拟面试、文档处理智能体。
4. **文档处理工作流**——ReAct（单任务）与 Plan-and-Execute（复合任务）双工作流，经注册表解析调用工具。
5. **管理面**——工具/工作流启停、调优参数在线热改、操作审计、模型路由管理。

## 三、整体架构

```
┌────────────────────────── 浏览器 ──────────────────────────┐
│  React SPA（React 18 + Vite + Tailwind + shadcn/ui）        │
│  Page → Hook（状态/副作用唯一出口）→ lib/api.js（唯一HTTP）  │
└──────────────────────┬─────────────────────────────────────┘
                       │ /api（Vite 代理，SSE 流式透传）
┌──────────────────────▼─────────────────────────────────────┐
│  Express 后端（10 层严格分层，依赖只允许自上而下）           │
│  L8  routes/* + management/manager     HTTP 路由            │
│  L7  workflows/*                       doc-react / doc-plan │
│  L6  tools/*                           注册的具体工具        │
│  L5.5 intents                          用户意图解析          │
│  L5  registry + agentRegistry          注册表（纯数据）      │
│  L4  docProcessor / unifiedSearch      领域编排             │
│  L3  llm.js                            LLM 流式调用         │
│  L2  chunker / embed / queryRewriter   算法（纯计算）        │
│  L1  milvusStore / vectorStore / sessionStore / questionBank│
│  L0  env / config / logger / errors / security / tunables   │
│  L9  index.js                          组装与启动            │
└───────┬──────────────────┬──────────────────┬───────────────┘
        │                  │                  │
   ┌────▼────┐        ┌────▼────┐        ┌────▼────┐
   │ Milvus  │        │ SQLite  │        │ Ollama  │
   │ 双向量   │        │ 会话WAL │        │ qwen2.5 │
   │ 集合×3  │        │         │        │ + bge-m3│
   └─────────┘        └─────────┘        └─────────┘
```

分层由 `server/scripts/check-layers.mjs` 静态断言（反向依赖 / 工作流直连工具 / lib 引 routes / 循环依赖 / 分层表缺登记），纳入 CI。

## 四、后端分层设计

| 层 | 职责 | 关键模块 |
|----|------|----------|
| L0 基础设施 | 环境、配置、日志、错误、追踪、安全、缓存、共享工具 | env / config / logger / errors / requestTrace / security / tunables / cache / llmProvider |
| L1 存储 | 数据持久化 | milvusStore / vectorStore（内存镜像缓存）/ sessionStore / questionBank |
| L2 算法 | 纯计算，无外部服务调用 | chunker（三层切片器）/ embed（含熔断器）/ queryRewriter |
| L3 LLM | 大模型流式调用 | llm.js（streamText、generateChunkAnnotations 分批标注） |
| L4 领域 | 跨模块业务编排 | docProcessor / unifiedSearch / chunkAudit / agents/builtin |
| L5 注册表 | 工具/工作流/智能体注册与发现（纯数据结构） | management/registry + audit / agentRegistry |
| L5.5 意图 | 用户意图解析 | intents.js（复合任务判定 → doc-plan 分发） |
| L6 工具 | 注册的具体工具实现 | tools/docTools |
| L7 工作流 | LLM 驱动的多步骤编排 | workflows/doc-react（ReAct）、doc-plan（Plan-and-Execute）、docWorkflowShared |
| L8 HTTP | 路由与响应、智能体分发 | routes/chat、routes/knowledge、management/manager |
| L9 入口 | Express 组装、中间件挂载、优雅关闭 | index.js（SIGTERM 先 flush Milvus 再排空 HTTP） |

**核心硬性规则**（详见 ARCHITECTURE.md 第二节）：

- 依赖只允许自上而下，禁止反向依赖与循环依赖。
- L7 工作流禁止直接 import L6 工具，必须经 `registry.resolveRunner(name)`。
- 存储统一走 L1：上层禁止绕过 vectorStore 直接操作 milvusStore。
- 内存缓存必须走 `TtlLruCache`（TTL + 上限 + 定时清理 `unref()`），禁止无界 Map。

## 五、前端架构设计

### 5.1 数据流（强制）

```
Page（视图组合，≤200行）→ Hook（状态/副作用唯一出口，≤200行）→ lib/*.js（API客户端）→ 后端REST
```

- 所有 HTTP 请求经 `lib/api.js` 的 `request()`：自动附加 `x-request-id`、AppError 归一化、204/流式统一处理。
- 禁止 Page/Component 直接调用 fetch；`useEffect` 只允许出现在 Hook 中。
- 无全局状态库：页面级状态由 Hook 管理，跨页共享的服务端数据复用同一 Hook。

### 5.2 知识库域 Hook 拆分

原 560 行的 `useKnowledgeBase` 拆为编排器 + 7 个单一职责子 Hook（列表 / 聚合 / 统计 / 预览 / 检索 / 变更 / 批量操作），对外接口保持兼容。

### 5.3 智能体插件化（ADR-002）

前端 `lib/agentDefinitions.js` 一行 `registerAgent()` 即完成注册，Sidebar / 路由 / 常量自动派生；后端 `agentRegistry.registerAgent()` 同构扩展，无需改动分发逻辑。

## 六、数据存储设计

### 6.1 Milvus 集合（单一数据源，无本地 JSON 对账）

| 集合 | 主键 | 向量字段 | 说明 |
|------|------|----------|------|
| kb_documents | doc_id | title_vector | 文档元数据 + 正文（VarLength 上限 60000） |
| kb_chunks | chunk_id | text_vector + question_vector | 切片双向量（dim=1024，COSINE），标量过滤下推 category/tags/owner |
| kb_memory | mem_id | text_vector | 跨会话事实记忆（ADR-007） |

关键机制：

- **内容哈希秒断重复**：sha256(content) → Set\<docId\> 内存索引，prepare/commit/旧上传三处拦截 409。
- **切片写入耐久**（ADR-004）：写完 flush + 强一致核实才置 indexed；启动 / health 孤儿对账 + reindex 自愈。
- **切片策略持久化**：delimiter 类策略参数存 `data/knowledge/doc-strategies.json`，编辑正文 / 重切时按原策略恢复，防止格式漂移。
- **去重**：批内余弦 ≥0.96 去重 + 跨文档检索相似度 ≥0.985 去重。

### 6.2 SQLite（会话）

WAL 模式；db 不可用时读操作降级返回空、写操作显式报错 `SESSION_DB_READONLY` / `SESSION_DB_UNAVAILABLE`，禁止在 db===null 时执行语句。

## 七、核心链路设计

### 7.1 RAG 检索管线（unifiedSearch，L4）

```
用户问题
  → queryRewriter 改写（LRU 缓存 + 超时降级 + 并发门控）
  → 混合检索：text_vector 语义召回 + question_vector 问题召回 + 2-gram 关键词覆盖率加权
  → 近重复折叠 + 单文档配额 + 分数融合
  → FAQ 近重复命中 → 直接应答（ADR-010）
  → streamRagAnswer：上下文注入 prompt → streamText → SSE Data Stream
```

### 7.2 切片器（chunker，L2）——三层结构

1. **规则递归**：标题 → 段落 → 句子逐级降级，按 maxChars 装箱；
2. **语义细切**：超长块句子 embedding 余弦相似度断点（阈值 mean-K·std，兜底 0.5）；
3. **上下文扩展**：前后各 2 句零成本拼接。

delimiter 策略为旁路：字面字符串 split（不 trim、支持换行/标题符），支持 overlapChars（0~500 字符滑动窗口重叠）。切片质量启发式评分（字数 50 + 结构 30 + 完整性 20）。

### 7.3 两段式上传（容错 + 前后端一致）

```
① prepare：抽文本+切片+评分，正文缓存进程内（TTL 30min/上限50份），秒级返回
② commit：一次性 previewId → 异步 job（chunking→embedding→indexing→done/error）
   轮询容错：连续 3 次失败才判死；判死后调用 POST /jobs/:id/cancel
   取消语义：进行中 → 入库前检查点拦截；已入库 → 回滚删除；已失败 → 幂等
```

### 7.4 模型管理（ADR-006）与降级策略（ADR-009）

- 模型档案 + 角色路由（chat / embedding / agent 三级）运行时热改，多模型可切换。
- **禁止静默降级**：模型 / Embedding / 存储不可用时显式报错并提醒；`LLM_STUB=1` 仅用于验证提醒链路。

## 八、安全设计（lib/security.js，ADR-001）

| 能力 | 机制 |
|------|------|
| CORS | Origin 白名单，生产未配置默认拒绝 |
| 认证 | AUTH_MODE=token + ADMIN_TOKEN 管理端点令牌校验 |
| 限流 | 进程内分层限流（chat / upload / search / management） |
| 上传 | 扩展名白名单 + 10MB 上限 + 内容类型校验 |
| 请求追踪 | x-request-id 白名单校验（防日志注入），pino 全链路 |
| 多用户隔离 | owner_id 按 principal 隔离（预览 / job / 文档 / 切片全链路） |

## 九、部署架构

```
Docker Desktop
├── milvus-standalone（+ etcd + minio 固定版本，milvus-compose.yml）
├── ollama（qwen2.5-coder:14b + bge-m3）
└── （可选）根 Dockerfile：frontend（Nginx 静态）/ backend（Express, HOST=0.0.0.0）双 target
```

- 本地启动顺序：Docker Desktop → Milvus 容器（`start-services.ps1`）→ 后端 3000 → 前端 5173。
- 优雅关闭：SIGTERM/SIGINT 先 flush Milvus 再排空 HTTP；SQLite WAL checkpoint 退出钩子。
- 运行数据与密钥：`server/.env`（不入库）、`server/data/`（不入库不删除）。
- CI：GitHub Actions（Node 22）跑 `npm run check:all`。
